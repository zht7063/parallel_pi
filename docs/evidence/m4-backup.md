# M4f：本机完整备份与手动升级流程

新增 `scripts/backup.py create/verify`。它在 Linux 后端停止后持有同一个 SQLite 实例锁，要求队列和持久操作已处理、所有监督 worker 已释放锁并持久化收束证据，才归档应用数据、原生配置、项目与绑定 worktree。原生会话/附件引用必须存在并被归档；未知数据库 schema 被拒绝。

备份包括未提交、未跟踪和忽略文件以及 Git/MWF 原生文件。SHA-256、条目列表、路径和固定版本进入清单；目录/文件采用 0700/0600。复制前后检查源文件元数据，输出不能嵌入源目录、不能覆盖已有备份。外部符号链接目标需显式纳入；普通配置字符串引用的外部资源由用户通过 --include 指定。

`tests/backup.test.ts` 使用真实 SQLite 和 Linux 监督器，验证：

- 活动后端实例拒绝备份，不产生输出。
- 未核对操作、queued 运行、失败交接保存和缺失原生会话文件拒绝备份。
- 外部符号链接缺少目标时拒绝，明确纳入后成功。
- 归档含未提交代码、记忆和凭据；解包数据库能读取原项目和事件，保持原路径。
- 目录/归档权限、已有备份不覆盖、归档损坏检测。
- 后端锁已释放但监督工具仍活着时拒绝；收束后成功；缺少收束证据仍拒绝。

专项 2 项测试通过，Python 语法、TypeScript 和格式检查通过。首次全量测试的唯一失败来自测试 teardown 先删除临时目录再停止监督器；已调整为停止并等待完成后删除，专项复验通过。最终 `npm run check` 全部 57 项测试、架构、类型及格式检查通过；交接检查与父目录 fsync 补充后，专项 2 项及类型/格式复验通过。本阶段不修改应用 UI 或运行时接口，未重复浏览器套件。

恢复和手动升级流程见 `docs/backup-upgrade.md`：先验证与暂存解包、保留当前新工作、按原路径明确恢复；不自动回滚用户代码。不实现跨机器路径重映射、后台更新或自动升级。旧版本原生样本探针不等于应用 A15 完成，完整升级验收继续在 M5 核对；本机 Linux 启动交付继续在下一阶段完成。
