# M4e2：原生 Git 提交事务核心

本段提供实际提交内容预览、整文件提交、钩子进度和不重放的恢复适配器。当前仍是经过真实 Git/监督器测试的基础能力：应用持久提交任务、HTTP/UI 显式提交入口及结果恢复界面尚待下一段接入，不能据此关闭 A13。

## 内容与范围

选择文件后，在私有索引中运行原生 clean filter，生成实际待提交树及 HEAD→该树的 diff。用户确认绑定这个树；执行时重新比较工作区修订与树。变更修订也包含显示的 diff，避免过滤器配置变化后原始文件字节相同却继续接受旧预览。选中的部分暂存/不支持路径拒绝提交；未选中的暂存或部分暂存路径保持原状。

实际执行使用原生 `git commit --only`，由私有事务索引承接原生 Git 操作。原 index 在独占 index.lock 下保留；成功后从备份索引仅更新所选路径并原子发布，失败不把准备过程写入用户暂存区。不 checkout、不 push、不 merge、不清理工作区；钩子自己产生的工作区修改按原生行为保留。

原生钩子通过本次调用的临时启动器执行，原文件、原参数、原路径及原先继承的 Git 配置环境保持可用。reference-transaction 在更新引用前核对父提交和完整树，钩子加入其他文件或改变已批准内容会导致拒绝更新引用。该机制基于 [Git 钩子文档](https://git-scm.com/docs/githooks) 和 [整文件提交语义](https://git-scm.com/docs/git-commit)，并在当前 Git 2.43.0 实测；没有使用 `--no-verify`。内部私有索引准备不触发用户的 index 通知钩子，真实 commit 的钩子照常运行。

## 恢复与进度

请求、原 index、所选路径、批准树、锁归属及引用事务证据保存在应用私有目录。调用方必须先获得原 worker 和后代进程已收束的证明，才能执行恢复；恢复只核对提交与整理索引，不重新运行 commit 或钩子。未开始与准备阶段中断分别处理；归属不明的锁、外部修改过的 index 或移动的分支返回 uncertain，不盲目覆盖。

真实钩子开始/结束及退出码从受监督 worker 返回。提交已经创建而 post-commit 被终止时，恢复返回 commit ID，同时保留钩子未完成的警告，不冒充全部钩子成功。提交 worker 的收束期限为五分钟，恢复为三十秒；超时不是提交未发生的证据，必须经过恢复核对。

- 私有索引准备中终止，清理已确认归属的锁，不创建提交；
- 已暂存删除和重命名两端，成功后工作区干净。
