# M4 阶段证据：配置、信任与模型

本文件记录 M4 的已完成部分，不代表 M4 或完整 MVP 验收结束。provider 自定义连接编辑、MWF 查看/修订与初始化、Git 成果、备份和本机 Linux 打包仍在实施范围内。

## 已接入的应用行为

- 全局默认模型和 API key 写回固定版 pi 的原生 settings/auth，读接口只投影允许显示的字段，密钥不回显。读取配置不执行 key 命令；显式模型目录查询由独立监督进程调用原生认证机制。
- 设置写入复用原生锁，在锁内核对进程级 HMAC 修订；首次文件创建使用排他写入。保留未知字段，拒绝过期和损坏配置，不用重置原文“修复”错误。
- 各 worktree 的默认模型独立写入 `.pi/settings.json`，信任选择保存在原生 `trust.json`。原生父目录继承与全局扩展信任钩子保持原优先级。配置 worker 和实际 RPC 的 trust resolver 一致，保存的决定来源和实际判定来源分别显示。
- 配置检查加载原生资源，因此占用分支维护名额，有持久化操作意图和监督 ID。中断后核验收束、标记检查中断并暂停；不自动加载第二遍扩展。显式恢复也纳入后端关闭等待。
- 新独立/接续会话显示来自原生工作区/全局的默认值，创建时固定；分叉仍沿用源会话当前模型。已有会话提供显式切换入口；原有运行中和排队项不被改写。
- 全局模型目录从固定版 ModelRuntime 读取，显示内置及 models.json 的 provider/model、图片能力和凭据可用性；不创建第二份注册表。扩展注册模型可填写 ID，执行前由真实 RPC 再次核验。
- SettingsDialog / ProjectSettingsDialog / 会话表单共用 AppDialog 与 ModelPicker。原生 select 的系统弹层外观是既定选择；AppDialog 统一提供未保存退出保护、焦点恢复和卸载提示。

## 直接证据

- `tests/configuration.test.ts`：真实原生文件修订、损坏保护、脱敏 HTTP、非法 JSON 不回显密钥；原生 trust store 读取应用修改；真实 RPC 与配置 worker 对保存决定/撤销/全局信任钩子的结果一致；真实原生目录与凭据变化。
- `tests/harness.test.ts` 新增配置检查场景：同分支互斥、不创建会话/运行、丢失应用确认后只恢复不重新加载、错误后保持暂停，以及关闭等待正在进行的显式恢复。
- `tests/project-settings.spec.ts`：真实仓库及 pi；工作区配置冲突、unknown 字段保留、信任与来源、另一个 worktree、窄窗口/键盘；运行中和排队项仍保留换模前的选择。
- `tests/settings.spec.ts`：真实 HTTP/原生文件、网络失败、外部修订、不同配置文件的草稿保护、API key 遮罩/清除、未保存退出、原生自定义模型目录实际选择。
- 浏览器使用可控 provider 测试运行和工具流程，并没有把它描述为真实外部模型调用；模型目录测试使用本地无服务端点，仅核验目录与认证可用性，不宣称测试过 provider 请求兼容性。

## 检查与限制

已完成构建、类型检查、36 项 Node 测试与 6 个浏览器场景；最终统一检查结果记录在里程碑中。共享 UI strict 静态审查为 0 errors / 0 warnings，DESIGN lint 为 0 errors / 1 warning（既有纯 Markdown 无 YAML frontmatter）。已查看 390px 工作区设置截图，表单可滚动，当前操作可达，无横向溢出。

文件锁无法约束不遵守锁的外部编辑器，原生后端原地写入不被描述为跨文件事务或断电原子保存。OAuth 凭据沿用原生配置；UI 当前支持 API key 编辑与凭据移除，不宣称提供 OAuth 登录向导。macOS 实机验证仍按用户决定后置。
