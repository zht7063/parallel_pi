| 项目 | 基线与边界 |

| MWF | commit `7b8be0e59647c90227c0cb945b279d7fa7ab14ef`，包版本 0.1.0；使用固定源码构建；pi-mcp-adapter 2.32.1 |

已保存的 Linux 全套探针结果为 32 通过、0 失败、0 跳过；DeepSeek `deepseek-flash` 的一次集成测试覆盖文字、工具、图片和会话恢复。部分探针验证的是缺口与保守阻止行为，不代表相应应用能力已经实现。本轮没有重跑探针或调用模型。

正式应用的依赖版本、后端框架、SQLite 驱动、地图组件，以及平台监督的具体机制在对应实现任务中确定并锁定。不得将探针运行时擅自描述为长期支持承诺；若改变运行时或固定依赖，应重做受影响的兼容验证。无需再次逐项征询已接受的架构与默认行为。

I02/I03 是首轮恢复能力的完成门槛。只有保守阻止而没有安全恢复路径时，可以保留实验结论，但不能宣称纵向闭环的恢复验收完成。I04–I06 的既有包装器依赖固定内部 API，适配实现必须保留相应兼容限制。

本表只追踪探针到应用的遗留事项，不替代完整 MVP 待办。地图导航与分叉、远端分支、设置、记忆纠正、diff/提交、多项目草稿、键盘与窄窗口仍按 A01–A16 补齐；阶段验收应逐项记录实际结果及证据。

## 顺序与延后范围

1. 建立应用骨架及依赖检查（I01），锁定本轮实际使用的库。
2. 实现真实纵向闭环（I02–I07 对应部分），先覆盖执行、持久化和故障恢复，再补完整交互。
3. 补齐地图、分叉、设置、记忆纠正、diff/提交等 MVP 流程，执行完整 A01–A16 应用验收。
4. MVP 完成后在用户 macOS 电脑运行安装、探针及应用验收，重点核对进程收束、文件锁与恢复。验证前保持 macOS 未验证标记。

更多 provider 与真实历史会话跨版本兼容尚无广泛证据，不作为当前开工门槛；扩大支持声明或升级内核时补充对应样本与验证。omp、自动更新检查、跨机器同步继续暂缓。
