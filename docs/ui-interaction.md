# 地图与会话：布局和交互讨论

状态：布局方案、预览与工作分离、地图浮层、浏览位置/草稿保留、双击快捷入口及项目切换区已确认；其余明确标注的建议尚待确认。当前仅讨论，不实施界面。

## 用户提出的布局

- 默认以全局地图为主体，图形化展示 Git 分支及其 session 节点。
- 左下角固定 pi 配置入口，以图形界面沿用 pi 的 provider、model 等配置方案。
- 配置按钮上方排列项目入口，可添加和切换项目；新添加项目位于最下方、紧邻设置按钮，旧项目依次上移。
- 右侧有可展开的详情面板；单击 session 自动展开并显示对应详情。
- 双击 session 进入专注会话视图，地图以较小缩略图转移到左上角。
- 在会话视图中，单击地图缩略图打开新面板查看地图；双击缩略图返回全局地图。

## 三种视图状态

| 状态 | 主体 | 辅助区域 | 进入方式 |
| --- | --- | --- | --- |
| 全局地图 | Git 分支与会话关系 | 左下角配置，右侧详情可折叠 | 默认或双击会话视图缩略图 |
| 专注会话 | 当前 session 对话与输入 | 左上角地图缩略图 | 双击 session |
| 会话中的地图面板 | 当前会话保留，打开地图面板 | 选中节点的详情 | 单击缩略图 |

“进入会话”仅切换查看/编辑界面，不自动提交消息、启动 agent、恢复文件或改变队列。浏览视图与运行状态独立。

## 已确认：预览与进入分开

右侧详情显示 session 标题、所属 Git 分支、运行/排队状态、简短结果和最近活动，并提供“进入会话”“新建接续会话”等明确按钮。可展示有限对话预览，完整对话与主输入区放在专注会话视图。

在会话中打开的地图面板作为应用内可关闭的浮层，不创建浏览器新窗口。它复用全局地图的数据和选择规则：单击节点预览详情，双击节点切换到该 session 并关闭面板。单击预览其他节点时，底层正在查看的会话不改变。

复用同一个地图面板实例；不因反复点击或在面板内导航而无限叠加面板。

## 单击与双击：已确认原则及实现建议

- 单击只做可撤销的选择/预览，不能启动任务；双击最终只产生一次进入/返回操作。
- 单击节点展开详情时，节点在鼠标下保持位置稳定，否则第二次点击可能落到别处。优先验证覆盖式或预留空间的详情面板，避免画布自动居中或缩放。
- 单击缩略图打开的地图面板不能覆盖缩略图或抢走第二次点击的目标；若布局无法保证，再为展开设置短暂的双击判定延迟，双击时取消待执行的单击动作。
- 节点双击不同时触发画布双击缩放；区分拖动画布与点击节点，避免拖动结束误进入会话。
- 双击只是快捷操作：提供“进入会话”“查看地图”“返回全局地图”按钮及键盘可达入口。键盘建议 Enter 预览，明确按钮进入，Esc 关闭最上层地图面板；输入法组字时不触发快捷操作。

## 浏览上下文：已确认原则及补充建议

- 从会话返回全局地图时恢复原缩放、平移、选中节点与详情开合状态，避免每次重新找位置。
- 保留各 session 的输入草稿、对话滚动位置；切换视图不取消后台 run，也不自动发送草稿。
- 建议左上角缩略图高亮当前 Git 分支和 session，提示其他分支运行/等待/失败状态；它是导航入口，不承担小尺寸文字阅读。
- 建议会话中的地图面板单独保存浏览视口，避免临时查看改变返回全局时的位置。
- 建议在会话视图中也保留可访问的 pi 配置入口；窄窗口通过按钮展开地图/详情，不强行并排挤压对话。

## 已确认：左下角项目切换区

项目列表位于 pi 设置按钮上方，支持添加和切换本机项目。按添加顺序从下往上排列：新项目插入底部，旧项目向上移动，不把“第一个”误解为列表最上方。

```text
[项目 A：最早添加]
[项目 B]
[项目 C：最新添加]
[pi 设置]
```

已确认：每个项目保留浏览位置和输入草稿，切换项目不停止原项目任务，项目入口显示“运行中／等待回答／失败”状态。

下列补充建议尚未确认：

- 单击项目切换当前查看的项目；普通切换不重排列表，只有添加新项目改变顺序。
- 全局和会话视图均保留项目入口，并明确标识当前项目；同名项目用路径区分。
- 建议将每个项目保留的浏览状态细化为视图模式、地图位置和选中 session，切回后恢复。
- 跨项目共用上限的调度实现见 MVP 规格；全局并发默认 2、可配置已确认。
- 项目较多时列表向上扩展到最大高度后内部滚动，pi 设置按钮保持固定。
- 添加项目失败不插入失效入口；同一项目重复添加时建议定位已有入口。成功后是否立即切换到新项目尚待确定。
- 如存在未保存的配置/记忆编辑，切换项目应保留其草稿或明确处理，不将其写入新项目。

## pi 配置：沿用原生方案

用户要求图形化沿用 pi 的配置。官方 [settings 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/settings.md) 当前描述了全局与项目配置，以及默认 provider/model；具体集成以最终固定提交为准。

已确认的配置分工：

- 全局设置主要统一配置 API key 等 provider 连接/认证信息。
- 每个项目可单独配置模型，每个 session 也可单独选择具体模型。
- 默认配置与当前会话模型分开；修改配置不悄悄改变运行中的任务。

建议的继承与生效细节（尚待确认）：新会话默认使用项目模型，未配置时回退到 pi 全局默认；会话显式选择优先。已有会话保持原模型，用户明确切换时在下一次执行生效。新建接续会话、历史分叉的模型继承仍见规格 D 项；每个任务入队时固定模型已确认，之后改默认不影响已有排队任务。

其他实现建议：

- UI 显示当前有效值、配置来源和保存范围；不另建一套与 pi 冲突的 provider/model 配置来源。
- 展示当前有效模型及其来源，保存时明确说明作用范围和生效时机。
- 全局设置以 provider 连接/认证为主，项目设置及会话视图提供模型选择；不将所有终端专属选项机械搬到 Web。
- 保存时保留未编辑字段；发现外部修改时先重新读取/对账，避免覆盖手动配置。
- 凭据由后端按 pi 适用的认证机制管理，不当成普通设置展示；不能把密钥存入浏览器持久存储或日志。

## 后续可验证的交互条件

1. 单击只选中/预览；双击进入正确 session，不重复导航或执行任务。
2. 展开详情不移动正在双击的目标；缩略图双击可稳定返回全局地图。
3. 全局与会话中的地图展示同一任务状态，临时预览不改变当前会话。
4. 返回全局地图恢复原浏览位置，切换 session 保留各自草稿。
5. 不使用双击也能通过按钮/键盘完成全部导航。
6. 失败、加载、空地图、长标题和窗口变窄时仍有清晰操作入口。
7. 添加项目后，新项目紧邻设置按钮，原项目依次上移；项目入口可切换到对应项目，地图和详情不会串用其他项目数据。

视觉配色、字体、像素尺寸、面板具体宽度、默认详情开合状态尚未定案。
