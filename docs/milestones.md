## 提交与证据规则

- 每段完成后更新本表及实际证据，检查 diff，再提交该段代码、测试和文档。提交采用 Gitmoji + Conventional Commits。
- 不提交凭据、运行数据、缓存、依赖目录或临时测试产物。上游子模块保持固定版本。
- 只有检查命令实际通过才记为通过。真实 pi、可控 provider 与真实外部模型分别标明，不能相互替代。
- M2 中无法核验旧进程时保持 recovering；必须同时实现有证据的收束与对账恢复路径，不能以永久阻止代替恢复完成。
- 每阶段仅建立已经使用的能力；不为未来内核、同步、多用户或自动更新增加空实现。
- 最终验收逐项记录步骤、结果、证据路径和限制；未完成条目继续实施，不通过缩减范围关闭目标。

## M2 已完成：执行与恢复闭环

截至本次检查，正式应用已完成以下闭环；探针不计入这些测试数字。

- SQLite 状态与事件同事务保存；规范路径/真实第二实例排他、事务中 SIGKILL 回滚已有证据。单文档元数据是当前明确规模限制，事件单独存表。
- Git 规范仓库身份、dirty 保留、worktree 创建意图与实际产物对账已接入应用。错误绑定及进行中的 merge/rebase 阻止执行。
- Linux 监督采用 Python 3 标准库 + prctl subreaper + flock + pidfd。启动前记录 boot ID/PID/starttime，以 waitpid ECHILD 核验收束；恢复 tombstone 阻止延迟启动。正常退出、double-fork/setsid 工具停止、后端 SIGKILL、启动窗口恢复、PID 世代冲突已有真实进程测试。
- 受监督真实 pi RPC 已接入：文本、工具、提问、图片、原生会话持久化、精确模型校验、持久幂等入队、分支 FIFO/跨分支并行、停止后暂停及明确恢复。运行结果与 lane 状态同事务提交。
- 本地 HTTP 具备 Host/Origin/会话校验；快照不暴露原生会话引用，SSE 按持久游标通知。真实浏览器可完成添加项目、创建会话、图片发送、草稿刷新恢复、丢失确认后的幂等重试、提问和停止/恢复。
- 每次实际运行结束先原子保存运行结果和交接保存意图，再向应用私有目录发布不可变 JSON 文件。交接记录包含来源、观察到的文本及事件游标范围，不宣称它是经验证的长期结论或完整语义摘要。最多保存 20,000 字符的观察文本，截断显式标记；完整证据仍在事件日志与原生会话。
- 交接文件失败不会把成功执行改成失败；该列暂停，待写内容保留。重试相同内容核对已有文件并 fsync，不重跑模型；不同内容不覆盖。明确暂不保存保留标记和审计事件，然后仍需用户恢复队列。后端重启将未确认保存转为可见待处理状态，不能自动重放任务。
- 新增真实文件失败、已发布但未确认的恢复、冲突文件保护和明确继续测试；浏览器新增交接失败/刷新/重试/键盘/390px 操作可达性验证。长错误提示放在会话滚动区，避免挤掉窄窗口操作区域。
